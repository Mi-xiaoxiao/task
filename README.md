# myls —— 纯 C 实现的 Linux `ls`

> 版本：2026-11-26 第一个完整版（支持 `-a -l -R -t -r -i -s` 任意组合）

## 一、简介

`myls` 不使用任何第三方库，仅依赖 POSIX / C 标准库，从零实现 `ls` 命令的核心功能。本版引入了**动态数组 + 翻倍扩容**，并补齐了 `-R` 递归、彩色输出、网格排版和多字段对齐。

设计目标：

- **功能完整**：7 个常用选项可任意组合；
- **界面友好**：列宽自适应、字段对齐、按文件类型着色；
- **工程规范**：防御性编程、动态内存管理、退出时释放全部资源。

## 二、编译与运行

```bash

./myls                               # 默认：多列网格
./myls -l                            # 长格式
./myls -a -l -i -s -t -r -R          # 任意组合

```

`getopt(argc, argv, "alistrR")` 负责解析短选项，重复选项和顺序无关。

## 三、支持的功能

| 选项 | 含义 | 实现要点 |
|---|---|---|
| `-a` | 显示隐藏文件（以 `.` 开头） | `show_all` 关闭过滤；`.` 与 `..` 一并显示 |
| `-l` | 长格式 | 权限 / 硬链接数 / 属主 / 属组 / 大小 / 修改时间 |
| `-i` | 显示 inode | `lstat().st_ino`，按最大宽度右对齐 |
| `-s` | 显示磁盘块数 | `st_blocks / 2`（KB），与本机 `ls -s` 单位一致 |
| `-t` | 按修改时间排序 | `cmptime()` 降序（新在前），同时间按名字排 |
| `-r` | 逆序 | 排序完成后整体首尾交换指针数组 |
| `-R` | 递归列出子目录 | 当前目录打印完毕后逐个 `do_ls(full_path)` |
| （默认）| 多列网格 | `print_grid()` 按终端宽度自适应列数 |

## 四、整体框架与实现逻辑

### 4.1 模块结构

```
main()                     解析选项，调用 do_ls(".")
 └── do_ls(path)            核心调度：读目录 → 排序 → 算宽度 → 输出 → 递归 → 释放
      ├── init / add / push       动态字符串数组（filelist）
      ├── cmpname / cmptime       qsort 比较器
      ├── turn_power              mode_t → "drwxr-xr-x"
      ├── getcolor                文件类型 → ANSI 颜色
      ├── print_grid              默认多列排版
      └── lstat + getpwuid/getgrgid + strftime    长格式字段
```

### 4.2 数据结构

```c
typedef struct filelist {
    char **names;      // 文件名指针数组
    unsigned int len;  // 当前元素数
    unsigned int cap;  // 当前容量
} filelist;
```

这是从"固定二维数组"到"动态数组"的关键升级：

- `init()` 初始容量 64；
- `add()` 检查容量，`newcap = cap * 2`，仍不够时直接取 `need`；
- `push()` 用 `strdup()` 复制文件名（不依赖 `readdir` 返回的缓冲区生命周期）；
- 结束时逐个 `free(names[i])`，再 `free(names)`。

### 4.3 核心流程 `do_ls()`

1. **读取**：`opendir(path)` → `readdir()` 循环，`-a` 关闭时跳过点文件，`push()` 进数组。
2. **排序**：`-t` 用 `cmptime()`，否则用 `cmpname()`（`strcmp` 字典序）；`-r` 时反转指针数组。
3. **宽度预扫描**：**第一遍**遍历，用 `snprintf(NULL, 0, ...)` 计算 inode / blocks / nlink / owner / group / size 的最大显示宽度，并累加 `sum_blocks`。
4. **输出**：
   - `-l / -s / -i` 任一开启 → 长格式单行输出，用 `%*d` 右对齐数字、`%-*s` 左对齐字符串；
   - 否则 → `print_grid()` 网格输出。
5. **递归**：`-R` 时对子目录打印 `路径:` 标题并递归调用自身（后序遍历，保证当前目录先输出完）。
6. **清理**：释放数组中每个字符串、数组本身，关闭目录流。

> 这种"**先扫描算宽度、再统一输出**"的两遍法是长格式对齐能做到位的关键。

### 4.4 几个值得注意的实现细节

- **`lstat` 而非 `stat`**：符号链接不会被解引用，`-l` 能正确显示 `l` 类型和链接本身的属性。
- **颜色延迟到输出时判断**：`getcolor()` 返回 ANSI 转义序列，只在 `isatty(STDOUT_FILENO)` 为真时写入，重定向到文件时自动无色。
- **网格按列填充**：`idx = c * rows + r`，与 GNU `ls` 的列优先排版一致（读的时候按列向下读才是排序顺序）。
- **时间格式化**：`localtime()` + `strftime("%Y年%m月%d日 %H:%M")`，失败时回退到"未知时间"。

## 五、特色与优势

1. **真正的动态扩容**：不再有 文件上限，也不浪费固定 256 字节/名字的空间。
2. **防御性编程到位**：`malloc` / `realloc` / `strdup` 全部检查返回值；`snprintf` 限制路径缓冲区；`localtime` 空指针检查。
3. **对齐做得细**：长格式每个字段单独计算最大宽度，数字右对齐、文本左对齐，视觉上和系统 `ls -l` 几乎一致。
4. **组合逻辑清晰**：所有选项都是全局标志位，输出分支只有"长格式 / 网格"两条，`-R` 递归统一放在末尾，不干扰当前层输出。
5. **无内存泄漏（正常路径）**：每个 `strdup` 都有对应的 `free`，`DIR*` 有 `closedir`。
6. **终端自适应**：`ioctl(TIOCGWINSZ)` 获取实际列宽，窄终端自动减少列数。
7. **纯 C、零依赖**：只用 `<dirent.h> <sys/stat.h> <pwd.h> <grp.h> <unistd.h>` 等标准头文件。

## 六、与 Linux 系统 `ls` 的差异

以下均在本机（`LC_COLLATE=zh_CN.UTF-8`）实测对比：

| 方面 | `myls` | 系统 `ls` | 原因 / 影响 |
|---|---|---|---|
| **排序规则** | `strcmp` 字节序：ASCII 在前，汉字按 UTF-8 字节（≈码点） | `strcoll` locale 序：数字 → 汉字（拼音）→ 字母 | `-r` 反转的是不同升序序列，所以输出顺序不同；详见 `myls_r_顺序差异分析.md` |
| **时间显示** | `2026年11月25日 20:16`（完整年月日） | `11月 25 20:16`（近期文件省略年份） | 格式串不同；`ls` 还会对 6 个月前的文件显示年份 |
| **"总计"行** | `总计132`（无空格） | `总计 132`（有空格） | 本机 `ls` 使用翻译后的 `total` 格式串 |
| **管道输出** | 始终网格排版 | 非 TTY 时自动单列 | `myls` 未检测 `isatty` 决定布局 |
| **`-R` 标题** | 只打印子目录标题，**没有**当前目录的 `.:` | 先打印 `.:` 再递归 | 小节标题缺失 |
| **路径参数** | 忽略，`myls /tmp` 仍列当前目录 | 列出指定路径 | `getopt` 后未使用 `optind` |
| **未知选项** | `getopt` 报错后继续列目录 | 报错并以状态码 2 退出 | 未做错误分支处理 |
| **颜色** | 硬编码 4 类：目录蓝、链接青、可执行绿、普通默认 | 遵循 `LS_COLORS` 环境变量，类型更丰富 | 可定制性不同 |
| **`-t` 精度** | `st_mtime` 秒级，相同则按名字 | 使用纳秒级时间戳 | 同秒内修改的文件顺序可能不同 |
| **其他选项** | 无 `-h -1 -F -d --help` 等 | 完整支持 | 本次任务范围所限 |

## 七、总结

`myls` 功能可以覆盖系统要求大部分内容的 `ls` 复刻：动态数组、两遍扫描对齐、颜色与网格排版、递归遍历等。与系统 `ls` 的差距主要集中在 **locale 排序（`strcmp` vs `strcoll`）**、时间格式、管道布局细节以及少量健壮性问题上。
